# 笔记写改与审查（note-checkup）

质量目标：**技术断言都站得住（正确性），该考的都讲了（完整性），复习时裸看这一页能恢复整个主题（表达兜底）**。
基准：原子笔记 `notes/ThreadPoolExecutor.md`，MOC `notes/线程池.md`。notes 只写 markdown + frontmatter，不碰 HTML/JS；重建 `node .build/build.mjs`。

## 写时流程（写/改一次成型）

1. **定位**：读同 MOC 相邻笔记，划清本篇分工——重复的收敛为双链指向主笔，缺口才由本篇讲。
2. **骨架**：frontmatter 三件套 → **`:::lede` 块（是什么）** → chain/branch 速查**按需**（序列型才写，见「chain 判据」）→ 导语（机制主线）→ 小节按因果排（机制 → 推论 → 边界 → 复盘），格式照下两节，别发明格式。
3. **成稿**：对照项目 AGENTS.md「文风与精简」+ 本 skill「精简规约」逐条自检——考点讲到机制层、结论性比喻配全边界、概念要么双链要么随文解释、callout/表格按规约。
4. **挂靠**：挂进对应 MOC；动 facet 则三处同步（正文双链 + `groups[].ids` + `traits`）。
5. **收尾**：`node .build/verify.mjs` + `node .build/vinea_check.mjs` 全绿。

## 速记 clip（极简 note，免 chain）

「问 AI 速记」：把粘来的重点压成极简卡片，不写 chain、不写完整因果小节。属 `note`（不新开 type），**只在收件箱 MOC `随问随记` 里出现**——学科 MOC 是面试八股墙，只收八股笔记，速记一律不回挂；速记与知识网的联系靠卡片内的出链指回学科概念。

骨架：

````
---
title: <主题> 速记
category: <学科，如 spring>
clip: true          # 速记标记：渲染时隐藏「密度」徽标（轻型捕获，结构密度无意义）
---
<导语一句：这是什么 + 一句定位，≥10 字，禁止报菜名>

## <主题小节 1>        # 具体术语，可多个；粘贴来的要点 / 代码直接摊在这里

## <主题小节 2>
…
````

规则：
- 顶部结构用「导语一句」替代 chain 块（微型/线性笔记本就允许），多节也不强制 chain。
- H2 用具体术语（如 `回滚规则`/`最佳实践`），禁编号与泛化占位；不强因果序。
- 代码块放正文 H2 节，别塞 `<details>`（同红线 #10）。
- 至少一条出链 `[[学科概念]]`：既避出链稀疏 WARN，也是速记并回知识网的唯一通路（它不回挂学科墙）。
- 落库：只挂进 `随问随记` MOC（收件箱），**别往学科 MOC 回挂双链**（含 facet 墙：`计算机网络` 这类注册了 `MOC_FACETS` 的墙要三处同步删 id/chip，别只删正文）；跑 `node .build/verify.mjs && node .build/vinea_check.mjs` 全绿。

## 精简规约（改稿默认动作）

同一考点用更少的字讲完。**删字不删点**：技术断言、数字、阈值、版本前提、双链一个不动，删的只是重复、低频与修饰。

必删清单：
1. **复述型复盘**——面试问答 / 常见误区里与正文重复的解释：答案压到 ≤2 句（结论 + 一个关键数字或机制名），整条与正文逐字重复的直接删。
2. **重复 callout**：正文已讲过的提醒不再发 callout；每篇 ≤3 个，多余的删或并入相邻 bullet。
3. **版本叙事**：演进史单独成节 → 压成一张两列表（**1.7 vs 1.8 这类对照是考点，保留表格，删叙述**）。
4. **低频延伸**：冷门 API 枚举、废弃开关、极端边界、教科书推导 → 删或压成一行 callout。
5. **散文包装**：「值得注意的是 / 简单来说 / 综上」类引导语、段首复述句、节末总结句、代码注释里复述代码的话。

压缩手法：长句拆 bullet（一条一事实）；能上表就上表；导语 ≤2 句；同义并列取最短的那个词。

硬指标（改完逐篇量）：正文 ≤6K 字符；面试问答 ≤4 题、常见误区 ≤3 条；开篇定义句 ≤2 句、导语 ≤2 句；callout ≤3。

不许动：chain/branch 骨架与节点数、frontmatter、`[[双链]]`、MOC 正文的双链清单（增删会改墙渲染）、表格的对比维度、所有数字与版本前提。

收尾：`node .build/verify.mjs && node .build/vinea_check.mjs` 全绿。

## 重复体检（改完必跑）

判据一句话：**同一件事全篇只准讲一遍**——留信息最全的那处当主笔，其余删掉或压成指针。删完复量正文字符数（硬指标 ≤6K），降幅就是这次精简的成效。

| 重复形态 | 症状 | 处理 |
|---|---|---|
| 枚举复数出现 | 同一组名词（目录、字段、参数）在定义段、表、结构树各列一遍 | 留信息最全那处（通常是树 / 表），别处删 |
| 散文复述结构块 | 同一序列既有散文又给了 chain / 表 | 删散文，散文独有的细节并进 chain 角标 |
| 复盘块复述正文 | 面试问答 / 误区逐条念正文结论 | 压到「结论 + 一个数字」，纯复述的删 |
| 导语复述数字 | 导语搬了正文的 token 数、字段约束 | 导语只写机制主线 |
| 表与 bullet 撞车 | 同一约束在表里、bullet 里各一份 | 表放约束，bullet 只留表装不下的细则与陷阱 |
| 两节讲同一机制 | 判定流程与加载分层各占一节 | 合并成一节，顶部 chain 同步减节点 |
| 跨笔记重复 | 边界句、对照结论与主笔笔记逐字相同 | 本笔记压成一行指针 + 双链指向主笔 |
| 文档间重复 | AGENTS 已立成规约，PITFALLS 又复述一遍 | PITFALLS 只留「触发 → 症状 → 修法」的坑 |

整理文档（PITFALLS / AGENTS / skill，非 notes）另做三步：

1. **删过时**：功能已迁出、代码已删的条目（如习录迁出后的 xilu 条目）。
2. **并重复**：通则与分节各写一份的，留通则 + 具体实例，删纯指针条目。
3. **反查引用**：`grep` 代码注释里的 `PITFALLS·<节名>` 与被点名的条目原文（如 `verify-features` 引「verify 断言已被移除的 UI」），节名 / 条目改了同步改指针，不留悬空。

## 组件语法

- **chain（线性流程 / 路线）**：`名称 | 位置/动作 | 状态` 三栏，4-5 节点，动词前置。**chain 判据（序列 vs 并列）**：节点换序就读不懂 → 写（机制流 / 判定流程 / 决策分流）；换序不影响理解 → 不写（概念释义、分类清单、横评对比、语法速查、全景导览都由导语带过）。另外两类一律不写：微型笔记（正文 <2.5K 字符或内容节 ≤3）、题卡（`category: leetcode`，骨架固定，链就是目录复读）。例：
  ```` ```chain
  七大参数 | 7 个旋钮 | 配置
  执行路径决策 | 任务如何路由 | 核心
  面试问答 | 高频考点 | 复盘
  ````
- **branch（选型分流 / 决策）**：`01: 节点` / `02: 节点` 打头，接 `- 名称 | 行为 | 备注` 行。例：
  ```` ```branch
  01: 缓存异常
  02: 按现象分流
  - 穿透 | 查不存在 key 打 DB | 布隆过滤器
  - 击穿 | 热点 key 失效 | 互斥锁
  ````
- **mermaid**：支持 8 类 —— `flowchart` / `sequenceDiagram` / `classDiagram` / `stateDiagram-v2` / `erDiagram` / `mindmap` / `quadrantChart` / `timeline`。默认包在 `<details>` 里折叠，打开后懒渲染、带入场动画。
  - `<summary>` 留空或写占位（图 / 图示 / 展开流程图…），build 按首关键字自动填「展开流程图 / 时序图 / 类图 / 状态图 / ER图 / 思维导图 / 象限图 / 时间线」；写了具体名字（如「线程状态迁移」）则原样保留。
  - **fence 语言一律写 `mermaid`**，图类型写在源码首行。build 只认 ` ```mermaid `（内部匹配 `language-mermaid`），写成 ` ```classDiagram ` / ` ```mindmap ` 会被当成普通代码块，图不渲染且不报错。
  - 例：
    ````
    <details>
    <summary>展开类图</summary>

    ```mermaid
    classDiagram
    class ThreadPoolExecutor
    ThreadPoolExecutor : - corePoolSize
    ThreadPoolExecutor : - maximumPoolSize
    ```

    </details>
    ````
- **gantt**：自定义 `` ```gantt `` 块（非 mermaid），由 build.mjs 渲染。
- **callout**：`> [!type] 标题` 后接正文/列表；`type` ∈ note/info/warning/tip/danger/caution/important/question，只承载单一提醒。
- **details（复盘块）**：`<details><summary>...</summary>` 包面试问答、常见误区、选型决策、速记、对比等；标签不限固定名，数量 0~N 自定。**只装文本与图（```mermaid``` / ```gantt```）——代码块一律放正文**，折进折叠块既压掉代码的存在感、又与 details 卡片撞成双层边框；`vinea_check.mjs` 已把「details 内含非图代码块」断言为 P1。
- **双链**：`[[笔记标题]]` 行内穿插，散布全篇，不单独成节；链接指向 `notes/` 下对应 md 的 slug。

## featured（MOC 专属）

```yaml
---
type: moc
featured: ThreadPoolExecutor   # 核心子笔记的 title 或别名，build 自动 slugify 解析；解析不到只在末尾打 ⚠
---
```

- **何时加**：MOC 子卡里有一篇「核心入口」（最常被打开、最该先读）时写；**没有核心入口就别写**，挂了反而显得子卡排序被强行拔高。
- **效果**：该子笔记在 MOC 墙上 `pinned=true` 永远第一，首页卷带根墙也顶到卷内第 1 位（谁在用：grep `featured` 即可）。

## 红线（违反即返工）

1. **顶部「思维链路速查」只在主干是序列时才存在，写的是机制流 / 判定流程 / 决策分流，不是章节目录**（例：HashMap 底层结构→哈希计算→寻址查询→扩容→面试），且不与正文任何 chain 撞脸；并列结构的笔记不写这块（判据见「chain 判据」）。
2. **chain 第一栏 = 流程节点名（有哪些步骤 / 分叉），不是章节名；导语 = 机制主线**（为什么这么读 / 这篇在讲什么），禁止把章节名按序用箭头串一遍。反例：「委派规则 → 源码实现 → 收益 → 面试复盘。」（报菜名）；合格例（同主题）：「一张加载请求先『向上问』、逐层落空才『向下装』——先立规则，再对照源码印证，随后回答为什么非这样设计不可」。导语允许机制结论、因果推进、概念钩子或双链，就是不许报菜名。
3. **lede 块 + 导语句永远在**：`:::lede` 块在 H1 之后、首个 H2 之前（块内首行写「X 是什么」，可选副行 `**标签：**` 渲染成 chip），导语在 chain 块之后（无 chain 则接在 lede 块后）、首个正文节之前（写机制主线）。chain/branch 块**按需**：只在主干是序列（机制流 / 判定流程 / 决策分流）时写，并列结构、微型笔记、题卡不写（判据见「组件语法·chain 判据」）。**lede 讲过的「是什么」，正文首节与导语都不许再讲一遍**（首个内容节直接从机制/为什么切入）。
4. **流程/步骤序列一律用 `chain`**；`callout` 只承载单一提醒，**禁止用 callout 罗列步骤流**。
5. **callout 遍布全篇**，有需要就用、不堆一处；**双链 `[[…]]` 行内散布，不单独成节**。
6. **chain/branch 块内不写「思维链路」小标题**（build.mjs 已去重）。
7. **MOC 默认走 wall 渲染**；可按需加 chain / branch / 深入节（描述性 H2），不禁止。
8. **结构化优先、少散文**：能用表格、callout、mermaid 说清的不写段落；链表/树/哈希表这类结构优先画出来，而非文字描述。
9. **H2 描述性具体术语**，禁编号（`## 1. xxx`）与泛化占位（详节/总结/详解）；深入/落地节按内容落点命名。
10. **`<details>` 内不放代码块**（` ```mermaid ` / ` ```gantt ` 除外）：要展示代码就开正文节（如 `## 落地：Spring 写法`），别塞进折叠块。机械断言在 `vinea_check.mjs`（P1）。
11. **一节三层封顶、主干唯一**：机制流程/步骤序列的主干只能有一处（chain 或表二选一），散文段只写前提、后果与陷阱。判据——删掉散文段后 chain/表是否仍完整，完整就删散文；「叙述段 + chain 同讲一个序列」违反即返工。
12. **职责三要素**：组件/注解/API 的职责要写全「范围 → 产物 → 边界」。只写动作句（如「扫包把 X 收进容器」）判为不完整，补三要素后就近加 callout 兜易漏项（起点、产物形态、与邻组件的边界）。详见项目 AGENTS.md「文风与精简」节。
13. **lede 块 = 本体定义，不是机制流也不是章节串**：模板「X 是<哪一类东西>，<解决什么 / 与相邻概念的边界>」——术语型写「是一种…机制」，组件型写「是…的组件，负责…（不负责…）」。写成「本文讲 A→B→C」或把正文机制压缩一遍都判违规（机制归导语与正文）。副行 `**标签：**` 只承载边界/载体/对比，不写第二层机制。

**子类主题色**（与 `build.mjs` 的 `ACCENT` 对应，改色去那改，这里只读）：java-collection 青绿 / javase 翠绿 / jvm 珊瑚红 / juc 亮紫 / spring 亮青 / architecture·system-design 亮橙 / network 天蓝 / mysql 亮蓝 / redis 鲜红 / mq 品红 / leetcode 金黄 / projects 玫红

## 体检（写后，或被点名「体检/查一下这篇」时）

按层执行，正确性优先；已断言化的不再人审，每轮修改后重跑机器校验，红了先修再继续。

### 第 0 层：机器断言（先跑，全绿才进人审）

```
node .build/verify.mjs && node .build/vinea_check.mjs
```

- verify 覆盖：语法冒烟、DOM 固定件、孤儿笔记（in-degree=0）、根可达性、mastery、spans、features、groups。
- vinea_check 覆盖内容级：P0 = frontmatter/title 缺失、fence 配对偶数、title 重复；P1 = 死链（**别名感知**，与 build 双链解析同口径）、H1==title、order 冲突、顶部结构、chain 栏数/节点数、编号与泛化 H2、summary 占位/重名、callout 配色；WARN = 出链稀疏（≤1）仅提示。⚠️ 改这个脚本时，按行匹配的正则必须容忍 `\r?\n`——notes 全是 CRLF，写死 `\n` 会静默失配（检查形同虚设还不报错）。

### 第 1 层：正确性（主体，一票否决）

做法：把笔记里的技术断言**逐条提取成真命题清单**——每个因果句、每个表格单元格、每条 callout、每个代码注释里的断言都算——然后逐条核对，不放过任何一句。

- **断言核对**：与真实机制比对。拿不准的不凭印象判对错，用 WebSearch 查官方文档、源码、权威资料后再下结论，并注明依据。发现错误直接给修正版写法。
- **数字复算**：例子里出现的字节数、次数、大小、行号、数值亲手算一遍。算不出来的示例补中间步骤。
- **边界反例**：每条结论找至少一个边界条件自问是否仍成立（无泛型通配的原始类型、并发下的交错时序、空/单元素输入、极端参数）。
- **版本前提**：涉版本差异的断言（Java 8/17、MySQL 5.7/8.0、Redis 各版本）必须标明适用版本；没标的要么补标注，要么改成跨版本成立的表述。
- **因果链完整**：推论必须有前提支撑，「所以/因此/可见」处逐一回查前提是否真在前文立住；结论性比喻/口号检查是否当场配全边界。

### 第 2 层：完整性（主体）

- **考点覆盖**：按项目记忆的考点基准盘点缺口，列「缺失考点清单」，每条注明是新增小节还是并入现有小节（例：Redis 持久化不能漏 AOF 重写；Java 泛型不能漏 PECS；MVCC 不能漏 RC 与 RR 的 ReadView 差异）。
- **深度匹配**：高频考点讲到机制层（为什么/怎么实现），不停在记忆型结论；低频点点到为止，不反向过度展开挤占篇幅。
- **相邻分工**：同 MOC 下相邻笔记有无重复讲或两边都没讲；跨笔记重复处收敛为双链指向主笔笔记；同一机制跨笔记口径必须互证一致（口径冲突属 P1）。
- **前置依赖闭环**：正文用到的概念，要么有对应笔记可 `[[双链]]`，要么随文一句话解释；两者都没有就是断链。

## 已裁决口径（勿反复推翻）

- 红黑树千万行树高写「约 24~46 层」（最坏 2·log₂n），别只写理想 24。
- 速记（`clip: true`）只在收件箱 `随问随记` 里出现：**不得回挂任何学科 MOC**（面试八股墙只收八股笔记，用户明确否掉）；收件箱本身是卷外常驻，只走壳层右上角 `clipDock`，不登记 `GROUP`、不写进 `MOC.md`。
- **缓存一致性卷口径（跨笔记必须一致，勿改回去，主笔 `notes/缓存与数据库一致性.md`）**：
  1. 缓存是副本、DB 是权威源：写只打 DB，缓存不接收新值；缓存值只能来自「读回源回填」或「写后失效」。
  2. Cache-Aside 的「旁路」落在写路径：读 = 命中返回 / miss 回源回填；写 = 更新 DB + 删缓存。
  3. 写后删而非更新：并发写乱序覆盖（缓存写入序 ≠ DB 提交序，最终留旧值）、富化对象重算成本高、改缓存失败留永久脏数据、冷数据白写；删除失败最坏是 cache miss，读会自愈。
  4. 顺序唯一正解「先更新 DB（最好 afterCommit）再删缓存」：先删缓存会让并发读回填旧值且此后无人再删，脏到 TTL 过期；正序残留窗口（读 miss + 读到提交前值 + 回填晚于删除）靠延迟双删 / 短 TTL 兜。
- **Java 锁卷三条口径（跨笔记必须一致，勿改回去）**：
  1. 偏向锁 = JDK 15 默认禁用、JDK 18 实质移除；凡讲锁升级的笔记都要带这句版本注，不能只画「无锁→偏向→轻量→重量」四段。
  2. volatile 原子性 = 「单次读/写 ✅；复合操作（i++）❌」。写「volatile 完全不保证原子性」是错的。
  3. StampedLock **可中断**（`readLockInterruptibly`/`writeLockInterruptibly`）、**可超时**（`tryReadLock(t)`/`tryWriteLock(t)`），不可重入、无 Condition 才是它的限制。对比表别写「可中断 ❌」。
