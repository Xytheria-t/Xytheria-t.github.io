# 缓存击穿

缓存击穿是一种缓存异常：某个被高频访问的热点 key 在失效瞬间，大量并发请求同时未命中、一起回源 DB 重建同一条数据。与缓存雪崩（大量 key 同时失效）、缓存穿透（key 根本不存在）的分界在范围——只坏一个热点。

## 思维链路速查

```chain
现象定义 | 单热点 key 击穿 | 区分
成因与危害 | 并发重建打 DB | 核心
解法全景 | 互斥/逻辑过期/预热 | 策略
三场景对比 | 见 MOC | 关联
面试问答 | 高频考点 | 复盘
```

击穿 = 某个被高频访问的热点 key 在失效瞬间，大量并发请求同时 miss → 同时回源 DB 重建，压垮单条数据查询。

## 现象定义

| 概念 | 触发 | 受影响范围 | 根因 |
|---|---|---|---|
| 缓存击穿 | 单个热点 key 失效 | 单点 | 热点 key 并发重建 |
| 缓存雪崩 | 大量 key 同时过期 / 宕机 | 大面积 | 过期集中或缓存层不可用 |
| 缓存穿透 | 查不存在的 key | 单点 | key 不存在，无缓存可命中 |

## 成因与危害

```chain
热点 key | 超高并发访问 | 挂了
TTL 到点 | 瞬间全 miss | 同时回源
无合并 | 每个请求各查一次 DB | 单查询被打爆
```

| 成因 | 典型场景 | 危害 |
|---|---|---|
| 热点 key 突增 + 到期 | 大 V 商品、首页爆款 | 单 SQL 被并发放大 |
| 无回源合并 | 每个线程各自查 DB | DB 连接 / CPU 飙升 |
| 重建慢 | 复杂查询 / 远程调用 | 等待期间请求堆积 |

## 解法全景

```chain
互斥重建 | 锁/单飞 | 合并回源
逻辑过期 | 异步续期 | 不阻塞读
热点预热 | 提前加载 | 抗峰
```

| 方案 | 做法 | 防什么 | 代价 |
|---|---|---|---|
| 互斥锁 / singleflight | 同一 key 只放一个请求回源，其余等待复用 | 并发重建 | 等待线程占用连接 |
| 逻辑过期 | value 内嵌过期时间，过期后异步重建，返回旧值 | 重建期间击穿 | 短暂返回旧数据 |
| 热点 key 预热 | 预估热点提前加载、长 TTL | 冷启动击穿 | 需预判 |
| 永不过期 + 异步刷新 | 物理 TTL 不设，靠后台任务刷新 | 任意时间点击穿 | 内存占用、一致性弱 |

> [!tip] 互斥 vs 逻辑过期
> 互斥锁简单、数据新鲜但等待占资源；逻辑过期不阻塞读但短暂返回旧值；可叠加：查到逻辑过期 → 异步重建 → 返回旧值。

> [!note] singleflight 实现要点
> 首个线程拿锁查 DB 回填，其余线程 `await` 同一结果；重建失败要放行下一个重试，避免「锁内失败、大家一起饿死」。

对照：[[缓存击穿]] 一个热点没了（本篇）；[[缓存雪崩]] 一整片没了（错峰 TTL / 多级缓存 / 熔断）；[[缓存穿透]] 压根没这个东西（布隆 / 空值缓存）。

<details>
<summary>面试问答 (2题)</summary>

Q：缓存击穿和缓存雪崩区别？

A：击穿是单个热点 key 失效、并发回源单条数据；雪崩是大量 key 同时失效或缓存层不可用。前者用互斥重建 / 逻辑过期，后者用错峰 TTL + 熔断。

Q：逻辑过期和物理过期区别？

A：物理过期由 Redis 直接删除，过期瞬间可能击穿；逻辑过期值自带过期时间、Redis 不删，读时判断并异步刷新，不阻塞但可能返回旧值。

</details>

<details>
<summary>常见误区 (2条)</summary>

- 误区：击穿 = 雪崩，解法一样。击穿是单点，靠互斥即可，不必上多级缓存。
- 误区：加锁会导致超时。锁只保护回源，singleflight 合并后等待方不重复查 DB。

</details>
