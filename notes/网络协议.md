# 网络协议

:::lede
网络协议（protocol）是通信双方为交换数据而共同遵守的规则集合，解决异构主机之间「怎么互通」的问题；它按功能分层组织，每层只管自己那一段约定。
:::

网络协议就是「通信双方约定好的规则」：语法管格式、语义管含义、时序管先后。规则一多就按功能切成层，每层只管自己的事、靠封装把数据一层层包下去；本篇只讲总览与分层分工，各层细节在对应笔记里。

## 协议三要素

| 要素 | 回答的问题 | 例子 |
|---|---|---|
| 语法 | 数据的格式 / 编码 | HTTP 请求行 `GET /path HTTP/1.1`、字段排列顺序 |
| 语义 | 字段的含义 / 要做什么 | 状态码 `200` 表示成功、`GET` 表示取资源 |
| 时序 | 事件顺序 / 速度匹配 | 三次握手顺序、请求-响应谁先谁后 |

## 为什么分层

- 大问题拆小：每层独立设计、独立演进、可替换——IP 层换不换不影响上层的 [[HTTP]]。
- 封装（encapsulation）：发送方逐层加首部，接收方逐层剥首部，每层只认自己那层的信息。
- 工程解耦：每层只与上下层接口打交道，屏蔽底层差异（以太网 / WiFi 对应用透明）。

## 分层模型对照

OSI 是理论七层，TCP/IP 是实践四层：

| OSI 层 | TCP/IP 对应 | 数据单元（PDU） | 代表协议 / 设备 |
|---|---|---|---|
| 应用层 (7) | 应用层 | 报文（message） | HTTP / DNS / SSH，见 [[HTTPS]] |
| 表示层 (6) | 并入应用层 | — | TLS（部分归此）、编码转换 |
| 会话层 (5) | 并入应用层 | — | 会话管理 |
| 传输层 (4) | 传输层 | 段（segment，TCP）/ 数据报（UDP） | [[TCP]] / [[UDP]] |
| 网络层 (3) | 网际层 | 包 / 数据报（packet） | IP / ICMP、路由器 |
| 数据链路层 (2) | 网络接口层 | 帧（frame） | 以太网、交换机 |
| 物理层 (1) | 网络接口层 | 比特（bit） | 网线 / 光纤 / 无线电 |

- 合并规则：上三层（应用 / 表示 / 会话）并为「应用层」，下两层（数据链路 / 物理）并为「网络接口层」；面试答「TCP/IP 几层」说四层，说五层是教学折中（把网络接口层拆开便于讲）。

## 封装与解封装

发送方自顶向下逐层包裹首部，接收方自底向上逐层拆开：

```chain
应用数据 | 原始 payload | 起点
传输层 | 加 TCP/UDP 头 → 段 | 寻进程
网络层 | 加 IP 头 → 包 | 寻主机
链路层 | 加帧头/帧尾 → 帧 | 寻下一跳
物理层 | 转比特流 | 上线上传
```

每层设备只处理到自己那层，越往上越「懂内容」：

```branch
01: 设备工作在哪一层
02: 按处理深度分流
- 中继器 / 集线器 | 物理层 | 只放大信号，不识帧
- 交换机 | 数据链路层 | 按 MAC 转发帧
- 路由器 | 网络层 | 按 IP 路由包
- 网关 / 防火墙 | 应用层 | 解析报文内容做代理/过滤
```

路由器只拆到网络层看 IP 头决定往哪跳，不关心里面是 [[TCP]] 还是 [[UDP]]、更不关心应用数据——这正是分层解耦的好处，换应用协议它完全无感。

## 落地：从报文看分层

- 一份 [[HTTP]] 响应在线上层层打包：以太网帧头（MAC）→ IP 头（源 / 目的 IP）→ TCP 头（端口 / 序号）→ HTTP 报文本体；Wireshark 的树状展开就是还原这层包裹。
- 接收方必须按「帧 → 包 → 段 → 报文」顺序剥，剥到哪层才认哪层：应用层拿到的已是剥净的 payload，首部在每层入口就被消费掉，不会透传给上层。

<summary>面试问答 (3题)</summary>

Q：什么是网络协议？三要素是什么？

A：通信双方约定好的规则：语法（数据格式 / 编码）、语义（字段含义 / 动作）、时序（事件先后 / 速度匹配）。

Q：OSI 七层和 TCP/IP 四层有什么区别？

A：OSI 是理论七层；TCP/IP 是实践四层，上三层并入应用层、下两层并为网络接口层。

Q：交换机、路由器、网关分别工作在第几层？

A：交换机数据链路层（按 MAC 转帧）、路由器网络层（按 IP 路由包）、网关 / 防火墙应用层（解析报文内容）。

</details>

<details>
<summary>常见误区 (3条)</summary>

- 误区：TCP/IP 是七层。它是四层，五层只是教学折中。
- 误区：路由器看端口决定转发。路由器在网络层只看 IP 地址，端口是传输层概念。
- 误区：应用层 payload 还带着 IP / TCP 头。首部在每层入口就被消费掉，上层拿到的是剥净的数据。

</details>
