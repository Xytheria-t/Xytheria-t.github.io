# 网络协议

## 思维链路速查

```chain
协议三要素 | 语法/语义/时序 | 定义
为什么分层 | 封装与解耦 | 动机
分层模型 | OSI 与 TCP/IP 对照 | 核心
封装与解封装 | 数据单元流转 | 机制
面试问答 | 高频考点 | 复盘
```

网络协议就是「通信双方约定好的规则」——语法规定格式、语义规定含义、时序规定先后顺序。规则一多就管不过来，于是按功能切成层，每层只管自己的事、靠「封装」把数据一层层包下去。立住「分层 = 把复杂协议拆成可替换的薄层」这个核心，OSI 与 TCP/IP 只是同一思想的两种切法，封装流程是必考推论。

## 协议三要素

| 要素 | 回答的问题 | 例子 |
|---|---|---|
| 语法 | 数据的格式 / 编码 | HTTP 请求行 `GET /path HTTP/1.1`、字段排列顺序 |
| 语义 | 字段的含义 / 要做什么 | 状态码 `200` 表示成功、`GET` 表示取资源 |
| 时序 | 事件顺序 / 速度匹配 | 三次握手顺序、请求-响应谁先谁后 |

> [!note] 三要素缺一不可
> 光有格式（语法）不知道含义（语义）就解析不了；光知道含义不约定顺序（时序）就会抢答或死锁。协议 = 三者合起来的完整契约。

## 为什么分层

- **大问题拆小**：每层独立设计、独立演进、可替换——IP 层换不换不影响上层的 [[HTTP]]。
- **封装（encapsulation）**：发送方逐层加首部，接收方逐层剥首部，每层只认自己那层的信息。
- **工程解耦**：每层只与上下层接口打交道，屏蔽底层差异（以太网 / WiFi 对应用透明）。

> [!tip] 分层是对「复杂度」的投降与驯服
> 不分层的话，一份应用数据要自己处理寻址、纠错、介质访问……全搅在一起无法维护。分层把「如何到达」和「送达后干什么」彻底分开。

## 分层模型对照

OSI 是理论七层，TCP/IP 是实践四层（教学常用五层，把网络接口层拆回数据链路 + 物理）。

| OSI 层 | TCP/IP 对应 | 数据单元（PDU） | 代表协议 / 设备 |
|---|---|---|---|
| 应用层 (7) | 应用层 | 报文（message） | HTTP / DNS / SSH，见 [[HTTPS]] |
| 表示层 (6) | 并入应用层 | — | TLS（部分归此）、编码转换 |
| 会话层 (5) | 并入应用层 | — | 会话管理 |
| 传输层 (4) | 传输层 | 段（segment，TCP）/ 数据报（UDP） | [[TCP]] / [[UDP]] |
| 网络层 (3) | 网际层 | 包 / 数据报（packet） | IP / ICMP、路由器 |
| 数据链路层 (2) | 网络接口层 | 帧（frame） | 以太网、交换机 |
| 物理层 (1) | 网络接口层 | 比特（bit） | 网线 / 光纤 / 无线电 |

> [!warning] TCP/IP 把七层压成了四层
> 上三层（应用 / 表示 / 会话）合并为「应用层」，下两层（数据链路 / 物理）合并为「网络接口层」。所以面试答「TCP/IP 几层」要说四层，说五层是教学折中（把网络接口层拆开便于讲）。

## 封装与解封装

发送方自顶向下逐层包裹首部，接收方自底向上逐层拆开：

```chain
应用数据 | 原始 payload | 起点
传输层 | 加 TCP/UDP 头 → 段 | 寻进程
网络层 | 加 IP 头 → 包 | 寻主机
链路层 | 加帧头/帧尾 → 帧 | 寻下一跳
物理层 | 转比特流 | 上线上传
```

每层设备只处理到自己那层，越往上越「懂内容」：

```branch
01: 设备工作在哪一层
02: 按处理深度分流
- 中继器 / 集线器 | 物理层 | 只放大信号，不识帧
- 交换机 | 数据链路层 | 按 MAC 转发帧
- 路由器 | 网络层 | 按 IP 路由包
- 网关 / 防火墙 | 应用层 | 解析报文内容做代理/过滤
```

> [!note] 路由器的视角
> 路由器只拆到网络层看 IP 头决定往哪跳，不关心里面是 TCP 还是 UDP、更不关心应用数据——这正是分层解耦的好处：换应用协议它完全无感。

## 落地：从报文看分层

> [!note] 抓包视角
> 一份 HTTP 响应在线上被层层打包：最外层是以太网帧头（MAC），里面是 IP 头（源/目的 IP），再里是 TCP 头（端口 / 序号），最里才是 HTTP 报文本体。Wireshark 的树状展开就是在还原这层包裹。

```text
[以太网帧头 MAC][IP 头 源/目的IP][TCP 头 端口/序号][HTTP 报文
  HTTP/1.1 200 OK
  Content-Type: text/html

  <html>...</html>   ← 应用层 payload，到这就到家了
]
```

> [!danger] 跨层不能跳着读
> 接收方必须按「帧 → 包 → 段 → 报文」顺序剥，剥到哪层才认哪层。应用层拿到的已经是没有链路 / 网络 / 传输首部的纯净 payload——首部在每层入口就被消费掉了，不会透传给上层。

<summary>面试问答 (5题)</summary>

Q：什么是网络协议？三要素是什么？

A：协议是通信双方约定好的规则，三要素：语法（数据格式/编码）、语义（字段含义/动作）、时序（事件先后顺序/速度匹配）。三者合起来才是完整契约。

Q：OSI 七层和 TCP/IP 四层有什么区别？

A：OSI 是先理论后实现，七层（应用/表示/会话/传输/网络/链路/物理）；TCP/IP 从实践总结，四层（应用层合并了上三层、网络接口层合并了下两层）。传输层用 TCP/UDP，网络层用 IP。教学常讲五层，把网络接口层拆回链路+物理。

Q：数据在各层叫什么？

A：应用层是报文，传输层是段（TCP）或数据报（UDP），网络层是包/数据报，链路层是帧，物理层是比特。每层加自己的首部，这就是封装。

Q：为什么 TCP/IP 没照搬 OSI 七层？

A：OSI 分层过细，表示层和会话层边界模糊、落地复杂；TCP/IP 从 ARPANET 先跑通再总结，够用就好，合并上三层和下两层，更贴近工程现实。

Q：交换机、路由器、网关分别工作在第几层？

A：交换机数据链路层（按 MAC 转帧），路由器网络层（按 IP 路由包），网关/防火墙应用层（解析报文内容）。集线器/中继器只在物理层放大信号。

<details>
<summary>常见误区 (5条)</summary>

- 误区：TCP/IP 是七层。它是四层；五层只是教学折中，把网络接口层拆开便于讲解。
- 误区：路由器看端口决定转发。路由器工作在网络层，只看 IP 地址；端口是传输层（TCP/UDP）的概念，路由器不拆到那层。
- 误区：应用层 payload 还带着 IP/TCP 头。首部在每层入口就被消费掉，上层拿到的是剥净的纯净数据。
- 误区：表示层和会话层没用。它们被合并进 TCP/IP 的应用层，但功能（加密/编码、会话保持）依然存在，只是没单独成层。
- 误区：分层后各层完全独立、互不影响。上下层通过接口耦合，下层故障（如 IP 不可达）上层（HTTP 超时）必然受影响——解耦的是设计，不是故障传播。

</details>
