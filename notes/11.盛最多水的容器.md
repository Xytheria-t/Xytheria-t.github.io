# 11. 盛最多水的容器

> 难度：中等 ｜ 套路：对向双指针（贪心）｜ Hot100

<details>
<summary>题目</summary>

给定一个长度为 `n` 的整数数组 `height`。有 `n` 条垂线，第 `i` 条线的两个端点是 `(i, 0)` 和 `(i, height[i])`。找出其中的两条线，使得它们与 x 轴共同构成的容器可以容纳最多的水。返回容器可以储存的最大水量。**说明：你不能倾斜容器。**

| 示例 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| 1 | `height = [1,8,6,2,5,4,8,3,7]` | `49` | 取第 2 条（高 8）与第 9 条（高 7），宽 7，`min(8,7) × 7 = 49` |
| 2 | `height = [1,1]` | `1` | 宽 1、高 1 |

</details>

## 思维链路速查

```chain
容量公式 | 矮边高 × 底宽 | 定义
起手最宽 | l=0 / r=n-1 | 起点
移动矮边 | 高边动必不变优 | 核心
指针推进 | 宽度单调减，n-1 步 | 收敛
面试问答 | 贪心正确性证明 | 复盘
```

容量被矮的那条边卡死，而底宽从两端起手就是最大值、之后只减不增——于是每一步唯一值钱的决策只有「换掉矮边」，被丢掉的那些组合又恰好都能被当前容量压住，所以一路夹逼不会漏掉最优解。

## 容量由什么决定

两条竖线 `l < r` 围出的水量：

```chain
高度 | min(h[l], h[r]) | 由矮边决定
底宽 | r - l | 两端最大
容量 | 高度 × 底宽 | 两者相乘
```

| 因素 | 取值 | 结论 |
| --- | --- | --- |
| 高度 | `min(h[l], h[r])` | 木桶效应 |
| 底宽 | `r - l` | 端点越远越大 |

> [!note] 木桶效应：水会从矮的一侧溢出
> 装水高度不可能超过任意一条边，所以取 `min` 而不是 `max` 或平均值——这是整个贪心的支点。

## 为什么起手在两端

任意一对 `(i, j)` 的底宽 `j - i ≤ n - 1`，而 `(0, n-1)` 正好取到 `n-1`。宽度最大这一端先占住，剩下要做的就是在宽度逐格缩小的过程中尽量换更高的边。

## 为什么只移动矮边

设当前 `h[l] < h[r]`，当前容量 `C = h[l] × (r - l)`。

```chain
以 l 为左端 | 任意 k ∈ (l, r] | 待排除
容量上界 | min(h[l],h[k]) ≤ h[l] | 高不过矮边
底宽上界 | k - l < r - l | 窄于当前
结论 | 全部严格小于 C | 安全丢弃
```

即对每个 `k ∈ (l, r]`：`min(h[l], h[k]) × (k - l) ≤ h[l] × (k - l) < h[l] × (r - l) = C`。所有「以 `l` 为左端」的候选都被 `C` 严格支配，**`l` 这一侧可以永久淘汰**，安全地 `l++`。

反过来，若移动高边 `r`，丢掉的是「以 `r` 为右端」的候选，它们以 `h[l]` 为上界但无法被 `C` 一致支配（`h[k]` 可能远大于 `h[l]`，只是被矮边拖累），漏解风险就在这里。

> [!warning] 等高时移哪边都行
> `h[l] == h[r]` 时，两侧同侧候选的上界都是 `h[l]`，无论移哪边，被丢掉的候选都 `≤ h[l] × (r-1-l) < C`。代码里写成 `if (h[l] < h[r]) l++; else r--;` 即可，等高走 `else` 分支完全正确。

> [!tip] 收敛性
> 每步宽度减 1，`l` 与 `r` 合计最多移动 `n-1` 次，所以是 O(n) 而非 O(n²)——指针只进不退，没有回退重扫。

## 复杂度

| 维度 | 复杂度 |
| --- | --- |
| 时间 | O(n)，双指针合计移动 n-1 次 |
| 空间 | O(1)，仅两个指针与一个最大值 |

## 代码骨架

```java
public int maxArea(int[] h) {
    int l = 0, r = h.length - 1, ans = 0;
    while (l < r) {
        int cur = Math.min(h[l], h[r]) * (r - l);
        ans = Math.max(ans, cur);
        if (h[l] < h[r]) l++;      // 淘汰矮边（等高时走 else，同样安全）
        else r--;
    }
    return ans;
}
```

> [!note] 循环条件与宽度
> 用 `l < r` 而非 `l <= r`：`l == r` 时宽度为 0，容量为 0，不可能是最大值。

## 边界与变体

- `n = 2`：只算一次容量，循环一轮结束。
- 高度全相等 `[5,5,5,5]`：每步都走 else 分支，答案 `5 × 3 = 15`。
- 严格递增 `[1,2,3,4]`：`h[l] < h[r]` 恒成立，一路 `l++`；实际评估三对 `(0,3)=3`、`(1,3)=4`、`(2,3)=3`，答案是 `4`——不是宽度最大的那对。
- 含 0 `[0,1,0,2]`：以 0 为边的容量为 0，指针自然跳过。

<details>
<summary>常见误区 (3条)</summary>

- 误区：认为应该移动高边「保留更高的墙」。高度由矮边决定，留着高边不换，容量上限永远卡在矮边上，宽度还在缩小，不可能变优。
- 误区：把 `min` 写成 `max` 或 `(h[l]+h[r])/2`。水会溢出，容量取矮边高度。
- 误区：以为要两层循环枚举所有组合。两端起手 + 矮边淘汰已经把被支配的候选整批排除，单层循环足够。

</details>

<details>
<summary>面试问答 (3题)</summary>

Q：怎么严格证明移动矮边不会漏掉最优解？

A：设 `h[l] < h[r]`，对所有 `k ∈ (l, r]`，容量 `min(h[l],h[k]) × (k-l) ≤ h[l] × (k-l) < h[l] × (r-l) = C`。也就是说所有「以 `l` 为左端」的组合都严格小于当前容量，它们不可能是最优解，可以整批丢弃。全局最优若用到 `l`，也必然出现在这些被丢弃的组合里——矛盾，故最优解一定在剩余区间中。

Q：这题和 [[42. 接雨水]] 都是水 + 双指针，思路差别在哪？

A：容器求**单个最大值**，两端夹逼、每步取 `max` 并淘汰被支配的矮边；接雨水求**每一列水量之和**，两端夹逼、每步结算矮侧一列（水位 = `min(左最高, 右最高)`），两侧最高要边走边更新。前者是排除式，后者是累加式。

Q：复杂度还能更低吗？

A：不能。任何算法至少要读到每个高度一次（否则改一个未读位置就能改变答案），下界 Ω(n)，双指针已达最优。

</details>
