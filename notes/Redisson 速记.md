Redisson 是 Java 库，把 Redis 操作翻译成 Java 对象调用：你用 `Map`/`Lock`/`Queue` 的方法，它背后帮你发 Redis 命令并处理分布式细节。

## 分布式锁 RLock

Redisson 最知名的能力，解决手写 Redis 锁的痛点：

- **可重入**：同一线程可重复获取同一把锁，不会自己锁死自己。
- **看门狗自动续期**：业务超时未完成时，后台线程自动延长锁过期时间（仅在不显式指定过期时间时生效）。
- **防误删**：锁的值绑定客户端唯一标识，确保不会释放别人的锁。

## Watchdog 看门狗机制

自动续期机制，解决「过期时间设多长」的矛盾：设短了业务没跑完锁就过期，设长了客户端宕机后其他线程等太久。

### 触发条件

调用 `lock()` 方法时**不指定** `leaseTime` 参数（默认 -1）才生效。显式指定过期时间会禁用 Watchdog，锁到期强制释放。

### 核心参数

`lockWatchdogTimeout` 默认 30 秒：既是锁的初始过期时间，也是每次续期后重置的时间。

### 续期流程

加锁成功后启动后台定时任务，每隔 `lockWatchdogTimeout / 3`（默认 10 秒）检查并续期：通过 Lua 脚本原子检查锁是否仍被当前线程持有，是则重置过期时间为 30 秒。任务递归调用自己，锁释放时自动停止。

> [!tip] 选择建议
> 耗时不确定的任务用无参 `lock()` 让 Watchdog 自动管理；已知耗时的短任务显式设 `leaseTime` 避免续期网络开销。

## 分布式集合

把 Redis 数据结构包装成 Java 集合接口，跨 JVM 共享：

| 类型 | 说明 |
| --- | --- |
| RMap | 分布式 Map，数据存 Redis |
| RSet / RList | 分布式 Set / List |
| RQueue / RDeque | 分布式队列 / 双端队列 |

## 分布式对象

- **RBucket**：通用对象桶，存任意序列化对象。
- **RAtomicLong**：分布式原子长整型，替代 Redis `INCR` 命令。

## 分布式服务

- **RTopic**：发布订阅，多节点间消息广播。
- **RCountDownLatch**：分布式闭锁，协调多节点任务同步。

## 典型场景

- 分布式锁：保证集群下只有一个节点执行关键操作（如扣库存）。
- 分布式缓存/会话：多个服务实例共享用户会话或缓存数据。
- 分布式任务协调：用队列或闭锁协调多节点任务执行。
