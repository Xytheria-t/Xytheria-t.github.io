# 56. 合并区间

> 难度：中等 ｜ 套路：排序 + 扫描合并 ｜ Hot100 序号：56 ｜ LeetCode 56

<details>
<summary>题目</summary>

`intervals[i] = [start_i, end_i]`，合并所有重叠区间，返回**不重叠**且恰好覆盖全部输入的区间数组。

| 示例 | 输入 | 输出 |
| --- | --- | --- |
| 1 | `intervals = [[1,3],[2,6],[8,10],[15,18]]` | `[[1,6],[8,10],[15,18]]` |
| 2 | `intervals = [[1,4],[4,5]]` | `[[1,5]]` |

</details>

乱序区间互相纠缠，按左端点排序后能合并的一定相邻，一趟扫描即可——O(n log n)，瓶颈在排序。

## 核心思路

```chain
原数组乱序 | 区间前后关系不明，无法线性扫 | 困境
按左端点排序 | 可并的区间必然相邻 | 前提
一趟扫描 | 维护当前合并段，交叠就扩右端 | O(n)
```

不排序只能两两比较（O(n²)）。

合并判定只看「当前段右端」与「下一段左端」：

```chain
cur.end < next.start | 不相交 → cur 收尾入答案 | 开启新段
cur.end ≥ next.start | 相交 → cur.end = max(cur.end, next.end) | 区间并入当前段
```

> [!note] 完全包含无需特判
> `[1,4]` 遇到 `[2,3]`：`max` 取的是当前段右端，被包含区间天然被吸收。

## 复杂度

| 维度 | 复杂度 |
|---|---|
| 时间 | O(n log n)，瓶颈在排序 |
| 空间 | O(log n)（排序栈）或 O(n)（结果集） |

## 代码骨架

```java
public int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[0] - b[0]);   // 按左端点排序
    List<int[]> res = new ArrayList<>();
    for (int[] in : intervals) {
        if (res.isEmpty() || res.get(res.size() - 1)[1] < in[0]) {
            res.add(in);                             // 不相交：收尾旧段，开新段
        } else {
            int[] last = res.get(res.size() - 1);
            last[1] = Math.max(last[1], in[1]);      // 相交：扩张右端（含被包含）
        }
    }
    return res.toArray(new int[0][]);
}
```

> [!tip] 免排序扫描的替代
> 差分数组 / 桶在值域有限时能压到 O(n)；本题值域是整个 int 范围，不可行。

## 边界与变体

- 空数组 / 单区间：原样返回，循环天然正确。
- 首尾相接 `[1,2]` 与 `[2,3]`：`2 >= 2` 判相交，合并为 `[1,3]`。

<details>
<summary>常见误区 (2条)</summary>

- 误区：排序还要管右端。只排左端点即可——交叠判定是拿「已并入段的右端」比下一段左端，右端不参与排序。
- 误区：`res.add(in)` 存原引用，后续会就地改 `intervals`；输入要复用就得先拷贝。

</details>

<details>
<summary>面试问答 (2题)</summary>

Q：为什么排序后一趟扫描就能保证不漏并？

A：区间按左端单调后，扫描到 `in` 时它要么与当前段交叠，要么左端更大且不相交——后者与更早的段更不可能交。

Q：合并区间和 [[Hot100-贪心]] 的区间调度题什么关系？

A：目标相反：本题求覆盖并集（贪心扩右端），无重叠区间 / 会议室求最大不重叠数（按右端排序选最早结束）。

</details>
