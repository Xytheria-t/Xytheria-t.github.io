# 56. 合并区间

> 难度：中等 ｜ 套路：排序 + 扫描合并 ｜ Hot100 序号：56 ｜ LeetCode 56

## 思维链路速查

```chain
核心思路 | 乱序不可合并 → 先按左端点排序 | 关键
合并判定 | 相交合并 · 包含吸收 | 核心
代码骨架 | 一趟扫描贪心 | 落地
边界与变体 | 空输入 · 完全包含 | 防坑
关联题 | 区间问题家族 | 拓展
```

乱序区间互相纠缠没法处理 → 按左端点排序后变线性 → 一趟扫描，能并则并、被包含则吸收 → O(n log n)。

## 核心思路

为什么要先排序？

```chain
原数组乱序 | 区间前后关系不明，无法线性扫 | 困境
按左端点排序 | 可并的区间必然相邻 | 前提
一趟扫描 | 维护当前合并段，交叠就扩右端 | O(n)
```

> [!warning] 排序是关键前提
> 不排序就只能两两比较（O(n²)）。按 `start` 排序后，**能合并的区间一定连续**，问题塌缩成一遍线性扫描。

合并判定只看「当前段右端」与「下一段左端」：

```chain
cur.end < next.start | 不相交 → cur 收尾入答案 | 开启新段
cur.end ≥ next.start | 相交 → cur.end = max(cur.end, next.end) | 区间并入当前段
```

> [!note] 完全包含的情况
> `[1,4]` 遇到 `[2,3]`：`next.end < cur.end`，直接跳过——max 取的是当前段右端，天然把被包含区间吸收掉，无需特判。

## 复杂度

| 维度 | 复杂度 |
|---|---|
| 时间 | O(n log n)，瓶颈在排序 |
| 空间 | O(log n)（排序栈）或 O(n)（结果集） |

## 代码骨架

```java
public int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[0] - b[0]);   // 按左端点排序
    List<int[]> res = new ArrayList<>();
    for (int[] in : intervals) {
        if (res.isEmpty() || res.get(res.size() - 1)[1] < in[0]) {
            res.add(in);                             // 不相交：收尾旧段，开新段
        } else {
            int[] last = res.get(res.size() - 1);
            last[1] = Math.max(last[1], in[1]);      // 相交：扩张右端（含被包含）
        }
    }
    return res.toArray(new int[0][]);
}
```

> [!tip] 免排序扫描的替代
> 想压到 O(n) 可用差分数组 / 桶：值域有限时计数差分后还原合并段；值域大（本题 int 范围）不可行，排序才是通用解。

## 边界与变体

- 空数组 / 单区间：直接原样返回，循环天然正确。
- 两个区间完全重叠：被 `max` 吸收，不产生重复段。
- 首尾相接（`[1,2]`、`[2,3]`）：`2 >= 2` 判相交，合并为 `[1,3]`——按题意相邻即合并。

<details>
<summary>常见误区 (2条)</summary>

- 误区：排序只排左端点，右端不排就乱套。交叠判定永远只依赖「已并入段的右端」，与后续区间左端比较即可，右端无需参与排序。
- 误区：修改的是原数组的引用导致答案被污染。`res.add(in)` 存入的是原引用，后续 `last[1] = max(...)` 会就地改 `intervals` 的元素——若输入被复用需 `new int[]{in[0], in[1]}` 拷贝入列。

</details>

<details>
<summary>面试问答 (2题)</summary>

Q：为什么排序后一趟扫描就能保证不漏并？

A：排序使区间按左端单调。扫描到 `in` 时，它与之前所有区间只有两种关系：与当前段的交叠可并入，或完全在其右（左端更大且与当前段不相交 → 与更早的段更不可能交）。每段只在离它最近的前段处判定一次即可。

Q：合并区间和 [[Hot100-贪心]] 的区间调度题什么关系？

A：同属「区间问题家族」但目标相反——本题求覆盖并集（贪心扩右端）；无重叠区间 / 会议室求最大不重叠数（贪心按右端排序选最早结束）。排序基准与贪心策略都要跟着目标走。

</details>
