# 类加载过程

:::lede
类加载过程是 JVM 把一份 `.class` 字节码变成可被程序使用的类型的完整生命周期：加载 → 链接（验证、准备、解析）→ 初始化 → 使用 → 卸载，执行主体是 [[类加载器]]。
**边界：** 读到字节码 ≠ 类可用 · 真正就绪在初始化 · 初始化由主动引用触发
:::

## 思维链路速查

```chain
生命周期全景 | 七个阶段 | 概览
连接三阶段 | 验证准备解析 | 拆解
初始化时机 | 何时触发 clinit | 关键
被动引用反例 | 不触发的反面 | 辨析
面试问答 | 高频考点 | 复盘
```

七个阶段里真正藏坑的是连接与初始化：验证 / 准备 / 解析各干什么、`clinit` 何时才被触发 —— 被动引用反例把「加载 ≠ 初始化」钉死。

## 生命周期全景

```chain
加载 | 读字节码生成 Class | 起点
连接 | 验证 · 准备 · 解析 | 衔接
初始化 | 执行 clinit 赋真值 | 激活
使用 | 实例化与调用 | 运行
卸载 | 类型被回收 | 终点
```

| 阶段 | 做什么 | 产物 / 副作用 |
|---|---|---|
| 加载 | 按全限定名读字节流，转方法区运行时结构，堆上生成 `Class` 对象 | 方法区类型数据 + 堆上 `Class` |
| 验证 | 文件格式 / 元数据 / 字节码 / 符号引用四轮校验 | 非法类文件抛 `VerifyError` / `ClassFormatError` |
| 准备 | 静态变量分配内存、赋**零值** | `static int a` → 0 |
| 解析 | 常量池符号引用替换为直接引用 | 指针 / 偏移量 |
| 初始化 | 执行编译器生成的 `<clinit>()` | 静态变量赋真值 + 静态块执行 |
| 卸载 | 类型不可达，方法区回收 | `Class` 与所有实例均不可达 |

> [!note] 解析：符号引用 → 直接引用
> 常量池里存的是**符号引用**（类全限定名、字段名 + 描述符等字符串），解析换成**直接引用**（方法区地址、字段偏移或方法句柄），此后指令直接寻址。
> 规范只要求 `checkcast` / `getfield` 等 17 条指令在执行**之前**完成解析，所以解析可在初始化前，也可延迟到首次使用（**动态解析**），这是运行时多态的基础。

## 连接三阶段

| 写法 | 准备阶段的值 | 原因 |
|---|---|---|
| `static int a = 123` | 0 | 真值在 `<clinit>` 中才赋 |
| `static final int b = 123` | 123 | 有 `ConstantValue` 属性，准备阶段直接写入 |
| `static final String s = "x"` | `"x"` | 同上，字面量编译期入常量池 |
| `static final int c = new Random().nextInt()` | 0 | 非编译期常量，无 `ConstantValue`，走 `<clinit>` |

## 初始化时机

六种**主动引用**触发初始化（规范严格限定）：

| 场景 | 示例 |
|---|---|
| `new` 实例化 | `new User()` |
| 访问静态变量 / 静态方法 | `User.count` / `User.init()` |
| 反射调用 | `Class.forName("com.x.User")` |
| 初始化子类 | 父 `<clinit>` 先执行完，才轮到子类 |
| 启动类 | 含 `main` 方法的类 |
| 接口默认方法 | 实现类初始化前，定义 `default` 方法的接口先初始化 |

> [!danger] `<clinit>` 会被加锁
> JVM 保证一个类的 `<clinit>` 多线程下只执行一次，其余线程阻塞等待；`<clinit>` 内耗时操作或死锁会造成**类加载死锁**，表现为线程卡在 `Class.forName` 或首次类访问处、无异常输出。

接口特例：接口也有 `<clinit>`，但初始化接口**不要求父接口全部初始化**，只有用到父接口的常量或默认方法时才触发。

## 被动引用反例

| 写法 | 是否触发 | 说明 |
|---|---|---|
| `Sub.value`（`value` 定义在 `Parent`） | 只初始化 `Parent` | 静态字段只认**声明它的类** |
| `new User[10]` | 不触发 | 数组类由 JVM 直接生成，元素类不初始化（归属见 [[类加载器]]） |
| `System.out.println(Const.COUNT)`（`static final` 字面量） | 不触发 | 编译期常量被内联进调用方常量池 |

> [!danger] `Class.forName` vs `loadClass`
> `Class.forName(name)` 默认 `initialize=true`，会执行 `<clinit>`；`ClassLoader.loadClass(name)` 只到加载。JDBC 早期靠 `Class.forName("com.mysql.cj.jdbc.Driver")` 触发静态块注册驱动，4.0 后改走 SPI，见 [[破坏双亲委派]]。

<details>
<summary>面试问答 (2题)</summary>

Q：`static int a = 1` 在准备阶段后 a 的值？

A：0。准备阶段只赋零值，`1` 在 `<clinit>` 中才写入；若声明为 `static final` 编译期常量，准备阶段即为 1。

Q：类的卸载条件？

A：`Class` 不可达、无该类实例，且加载它的 [[类加载器]] 可回收；Bootstrap 加载的类基本不可卸载。

</details>

<details>
<summary>常见误区 (2条)</summary>

- 误区：加载完就初始化。中间还隔着验证、准备、解析，`loadClass` 只到加载阶段。
- 误区：常量传播让 `Const.COUNT` 触发 `Const` 初始化。编译期内联后运行期与 `Const` 已无字节码联系，改常量值必须重新编译引用方。

</details>
