# 双亲委派模型

:::lede
双亲委派模型是 `ClassLoader` 加载类时遵循的一条代码约定：加载请求先沿父加载器链向上传递，整条链都加载不到才由发起者自己加载。它是可绕过的实现约定、而非 JVM 规范的强制语义，[[破坏双亲委派]] 讲的正是对它的偏离。
:::

## 思维链路速查

```chain
委派规则 | 请求如何向上传递 | 规则
源码实现 | loadClass 三步 | 原理
收益 | 为什么必须这样设计 | 价值
面试问答 | 高频考点 | 复盘
常见误区 | 认知纠偏 | 收尾
```

一张加载请求先「向上问」、逐层落空才「向下装」——先立规则，再对照源码印证，最后回答为什么非这样设计不可。

## 委派规则

| 步骤 | 动作 | 结果 |
|---|---|---|
| 1 | `findLoadedClass` 查本加载器缓存 | 命中直接返回 |
| 2 | 委派 `parent.loadClass`，逐层上抛至 Bootstrap | 父层失败抛 `ClassNotFoundException`，被吞掉后继续 |
| 3 | 自己 `findClass` 读字节码 → `defineClass` | 仍失败，才由本层抛出 `ClassNotFoundException` |

JDK 9+ 的边界：加载前先判模块归属，模块已定义给某个加载器则由它直接加载，不再是纯父子链。

> [!warning] 术语纠正
> 「双亲」是 parent 的翻译，**不是两个父加载器**：除 Bootstrap 外每个加载器只有一个父，链路是单链。

## 源码实现

```java
protected Class<?> loadClass(String name, boolean resolve) throws ClassNotFoundException {
    synchronized (getClassLoadingLock(name)) {
        Class<?> c = findLoadedClass(name);                             // 1. 查缓存
        if (c == null) {
            try {
                if (parent != null) c = parent.loadClass(name, false);  // 2. 委派父加载器
                else c = findBootstrapClassOrNull(name);                // 3. 链顶向 Bootstrap 探测
            } catch (ClassNotFoundException e) {
                // 父层失败不处理，下一步自己加载
            }
            if (c == null) c = findClass(name);                         // 4. 自己加载
        }
        if (resolve) resolveClass(c);                                   // 链接（解析）
        return c;
    }
}
```

> [!tip] 自定义加载器的正确姿势
> 重写 `findClass`，**不要**重写 `loadClass`——后者绕过委派逻辑，等于主动破坏模型，见 [[破坏双亲委派]]。

## 收益

| 收益 | 机制 | 反例后果 |
|---|---|---|
| 类的唯一性 | 同一个类总由同一个加载器加载 | 同名类是**不同类型**，`instanceof` 与强转全失败 |
| 沙箱安全 | 核心库只认 Bootstrap 的搜索范围 | 自定义 `java.lang.String` 永远轮不到被加载 |
| 避免重复加载 | 父层缓存命中即返回 | 内存中多份同名 `Class`，静态字段各存一份 |

> [!danger] 同名类 ≠ 同一个类
> 判据是**加载器 + 全限定名**：两个加载器各载一份 `com.x.User`，`equals` 为 false、互转抛 `ClassCastException`。隔离机制见 [[类加载器]]。

<details>
<summary>面试问答 (3题)</summary>

Q：为什么设计双亲委派？

A：保证类的唯一性（同一个类只产生一份 `Class`）与沙箱安全（核心类不可被替换），顺带避免重复加载。

Q：如何破坏双亲委派？

A：三种典型方式：重写 `loadClass`、用线程上下文类加载器（TCCL）、自定义加载器做隔离。详见 [[破坏双亲委派]]。

Q：可以用自定义类加载器加载 `java.lang.Object` 吗？

A：不行。`java.` 开头的包名会触发 `defineClass` 的安全校验抛 `SecurityException`；即使绕过，Bootstrap 也会先返回官方版本。

</details>

<details>
<summary>常见误区 (3条)</summary>

- 误区：双亲委派是 JVM 规范强制的。它是 JDK 1.2 引入的**代码实现约定**，`ClassLoader` 是普通类，能被覆盖。
- 误区：「父加载器」是继承关系。实际是**组合**（`parent` 字段），不是 `extends`。
- 误区：委派失败立刻抛异常。`loadClass` 吞掉父层 `ClassNotFoundException` 后继续自己加载，只有自身也找不到才抛出。

</details>
