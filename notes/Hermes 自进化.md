# Hermes 自进化

:::lede
**Hermes 自进化** 是 Hermes Agent 把执行经验沉淀成技能、再用进化算法持续改写技能文本的能力。
**边界：** 优化外置文本资产 · 模型权重不动
:::

## 思维链路速查

```chain
任务执行 | 工具调用产出轨迹 | 输入
经验沉淀 | 难题落成 SKILL.md | 在线
检索复用 | 相似任务调出技能 | 复用
离线进化 | GEPA 反思改写文本 | 离线
门控合并 | 约束校验 + 人工 PR | 收口
```

自进化的分水岭不是「能不能自己改」，而是改完之后凭什么算变好——Hermes 把这条判据落在评估集与约束门控上：线上跑出来的经验只是原料。

## 两条路径：沉淀与进化

Hermes Agent 的骨架是 [[AI Agent]] 循环叠上持久记忆与技能库。官方口径里的「自动创建技能」只覆盖沉淀那一条：解决难题后写下一份可复用技能文档，格式即 [[AI Agent Skill]] 的 `SKILL.md`。

| 路径 | 触发 | 产物 | 有无判据 |
|---|---|---|---|
| 在线沉淀 | 难题被解决 | 新增或修订技能文档 | 无，靠后续复用检验 |
| 离线进化 | 人工发起 | 技能、提示、工具描述的候选变体 | 有，评估集 + 约束门控 |

沉淀只写不评，技能落盘即生效；构成进化的只有离线那条——同一份文本先有基线、再有变体、最后用评估集比出高下。

> [!note] 记忆不是进化
> 跨会话记住偏好属于记忆（沉淀事实），改写技能属于进化（优化能力）。两者共用一份存储，但只有后者需要评估集。

## 为什么用 GEPA 而不是 RL

GEPA（Genetic-Pareto）是集成进 DSPy 的提示优化器，ICLR 2026 Oral。它采样轨迹（推理、工具调用、工具输出）后**用自然语言反思诊断失败原因**，据此提出并测试提示改动，再从自身尝试的 Pareto 前沿上组合互补经验。

| 对比 | GEPA | GRPO 类 RL |
|---|---|---|
| 改动对象 | 提示与技能文本 | 模型权重 |
| 所需 rollout | 少量即可起步 | 常需数千次 |
| 学习信号 | 轨迹反思出的自然语言规则 | 稀疏标量奖励 |
| 硬件 | 纯 API 调用，无需 GPU | 需要训练卡 |

论文在 6 个任务上测得：平均超 GRPO 6%、最高 20%，rollout 用量最多少 35 倍；比同类提示优化器 MIPROv2 高 10% 以上（AIME-2025 +12%）。落到 Hermes 的成本量级约 $2–10 一次优化。

> [!tip] 冷启动门槛低
> GEPA 少量 rollout 就能出增益，新技能不必攒够真实数据再优化——先用强模型合成一批用例即可开工。

## 五个阶段的优化对象

| 阶段 | 对象 | 引擎 | 状态 |
|---|---|---|---|
| 1 | 技能文件 SKILL.md | DSPy + GEPA | 已实现 |
| 2 | 工具描述 | GEPA | 计划 |
| 3 | 系统提示分段 | GEPA | 计划 |
| 4 | 工具实现代码 | Darwinian Evolver | 计划 |
| 5 | 无人值守循环 | — | 计划 |

- 工具描述每次 API 调用都要发，硬上限 500 字符；参数描述 200 字符；参数名、类型、必填字段**冻结**，只有文本可进化。
- 工具描述进化治的是「选错工具」：执行追踪显示模型老在 `search_files` 与 `terminal(grep)` 之间摇摆，GEPA 就改写前者描述，把两个工具的边界拉开。
- 系统提示影响全部会话，且改动会让提示缓存整段失效，因此只离线优化、整版部署。
- 阶段串行：上一阶段拿不出可验证增益，就不进入下一阶段。

## 评估集从哪来

| 来源 | 做法 | 适用 |
|---|---|---|
| 合成 | 强模型读技能后造 15–30 个「任务 + 期望行为」对 | 冷启动 |
| 会话挖掘 | 从真实会话捞样本，LLM-as-judge 按 rubric 打分 | 越用越准 |
| 黄金集 | 手写 JSONL 存进本地数据集目录 | 关键技能 |
| 专属评估 | 植入 bug 看是否捕获、搜已知论文看是否命中 | 有客观判据的技能 |

期望行为写的是评分标准（如「应指出第 42 行的 SQL 注入」）而不是精确文本，因为多数技能没有唯一正确答案。适应度由 LLM 按 rubric 打三项分：是否遵循技能流程、输出是否正确有用、是否在 token 预算内。

## 护栏与边界

- 候选变体必须过：测试套件全绿、技能 ≤15KB、对话中途不改缓存、语义不偏离原始目的。
- 所有改动只产出 PR 交人工合并，靠 git revert 回滚——自进化不直接写主分支。
- 局限：评估集质量决定上限；进化搜索会陷局部最优；人工审查是吞吐瓶颈。
- 优化对象只有文本，底层模型仍是天花板：小模型驱动时，多步任务仍会在中途跑偏。

<details>
<summary>面试问答 (4题)</summary>

Q：Agent 自进化和 RL 微调的区别？
A：自进化改外置文本（技能、提示、工具描述），权重不动、无需 GPU；RL 改权重，常需数千次 rollout。

Q：GEPA 为什么比 RL 省？
A：它读执行轨迹用自然语言反思失败原因，把诊断直接写成提示改动；RL 只能从稀疏标量奖励里反推。

Q：进化出的变体怎么防止改坏？
A：先过约束门控（测试全绿、体积上限、语义保持），再以 PR 形式交人工合并，可 revert。

Q：系统提示为什么不能在线改？
A：改它会让提示缓存整段失效并影响所有会话，所以只离线优化、整版部署。

<details>
<summary>常见误区 (3条)</summary>

- 误区：自进化 = 模型自己改权重。→ 改的是文本资产；改权重走的是导出轨迹配 Atropos 跑 RL 的另一条链路。
- 误区：线上自动写技能就是进化。→ 那是记忆沉淀，缺评估与选择环节，不构成进化。
- 误区：进化能突破模型上限。→ 优化对象只有文本，底层模型决定能力天花板。
