# 基本数据类型

:::lede
基本数据类型是 Java 里由语言直接定义、非对象的一类类型：值直接存在变量中（局部变量占栈帧的局部变量表），位宽与取值范围由规范固定，不参与堆分配。与包装类相对，只有对象类型才能进集合与泛型。
:::

```chain
八种类型全表 | 位宽与取值 | 速查
整数溢出与浮点精度 | 两个精度陷阱 | 核心
字面量与转换 | 后缀与提升 | 规则
装箱与缓存 | 包装类 | 分野
```

八种类型先混个脸熟，坑全藏在「边界」里：整数溢出与浮点精度是数字的坑，后缀与类型提升是表达式的坑，装箱缓存让 `==` 也成了坑。

## 八种类型全表

| 类型 | 位数 | 字节 | 默认值 | 取值范围 | 包装类 |
|---|---|---|---|---|---|
| byte | 8 | 1 | 0 | -128 ~ 127 | Byte |
| short | 16 | 2 | 0 | -32768 ~ 32767 | Short |
| int | 32 | 4 | 0 | -2³¹ ~ 2³¹-1 | Integer |
| long | 64 | 8 | 0L | -2⁶³ ~ 2⁶³-1 | Long |
| float | 32 | 4 | 0.0f | 约 ±3.4e38，7 位有效数字 | Float |
| double | 64 | 8 | 0.0d | 约 ±1.8e308，15 位有效数字 | Double |
| char | 16 | 2 | '\u0000' | 0 ~ 65535（无符号） | Character |
| boolean | 未规定 | 未规定 | false | true / false | Boolean |

- 默认值只属于**成员变量**：局部变量不赋初值读取直接编译报错；数组元素由 `new` 自动填默认值。
- `char` 是唯一的无符号整型，存 UTF-16 码元，能当 16 位无符号整数运算，`'A'` 与 `65` 等价。
- `boolean` 位宽由虚拟机实现决定：单独使用通常按 int（4 字节），`boolean[]` 里多数按 byte（1 字节）——答「1 位」「1 字节」都不严谨。

## 整数溢出

`Integer.MAX_VALUE + 1 == Integer.MIN_VALUE`：整数运算溢出**不抛异常**，按二进制补码绕回，是线上金额 / 计数类 bug 的经典来源。

| 场景 | 写法 | 结果 |
|---|---|---|
| int 越界 | `2147483647 + 1` | -2147483648 |
| 大数相乘再转型 | `long t = 24 * 60 * 60 * 1000 * 1000` | 先按 int 算，已溢出才转 long |
| 求中间值 | `(l + r) / 2` | l+r 可能溢出 |
| 取绝对值 | `Math.abs(Integer.MIN_VALUE)` | 仍是负数 -2147483648 |

修法：常量先把运算抬到 long（上例带 `L` 得 86400000000，不带是 500654080）；求中点写 `l + (r - l) / 2`；JDK 8 起用 `Math.addExact` / `multiplyExact`，溢出抛 `ArithmeticException`，把静默错误变成显式失败。

## 浮点精度

```branch
01: 浮点比较
02: 按写法分流
- a == b | 位模式严格相等 | 0.1+0.2 != 0.3
- Math.abs(a-b) < 1e-6 | 允许误差 | 一般工程够用
- BigDecimal.compareTo | 精确十进制 | 金额必用
- Double.compare | 处理 NaN 与 ±0.0 | 排序场景
```

> [!danger] 0.1 + 0.2 != 0.3
> 二进制浮点无法精确表示 0.1，`0.1 + 0.2` 得到 `0.30000000000000004`——**金额计算一律 `BigDecimal`**，不用 float / double。

- `float` 有效数字只有约 7 位，整数部分一大、小数就不保真；字面量必须带 `f`，`float x = 0.1;` 编译不过（`0.1` 默认 double，大转小要强转）。
- `NaN` 与任何值比较都是 false（`NaN != NaN` 为 true）；`1.0/0.0` 得 `Infinity` 不抛异常，判空要显式用 `Double.isNaN` / `isInfinite`。

## 字面量与类型提升

| 字面量 | 默认类型 | 说明 |
|---|---|---|
| `100` | int | 整数字面量默认 int |
| `100L` | long | 后缀 L/l，建议大写 |
| `0.1` | double | 小数字面量默认 double |
| `0.1f` | float | 后缀 F/f |
| `0x1F` / `0b101` | int | 十六 / 二进制，JDK 7 起支持 |
| `1_000_000` | int | 下划线仅分隔，编译期丢弃 |
| `'A'` | char | 单引号 |

- `byte`、`short`、`char` 参与算术**先整体提升为 int**：`byte b = 1; b = b + 1;` 编译报错（int 不能赋回 byte），`b += 1;` 能过（复合赋值自带隐式强转）。
- 自动转换方向 `byte/short/char → int → long → float → double`；byte / short / char **各自独立**提升为 int，不存在 `byte → short`。
- `long` 转 `float` 会自动发生（float 范围更大），但 float 只有 24 位有效位、long 有 63 位，高位会被截断——看范围不代表看精度。

## 装箱与缓存

| 包装类 | 缓存区间 | 说明 |
|---|---|---|
| Byte / Short / Integer / Long | -128 ~ 127 | `valueOf` 复用对象 |
| Character | 0 ~ 127 | |
| Boolean | true / false | 全部缓存 |
| Float / Double | 无 | 浮点区间内取值无限，无法缓存 |

> [!danger] 127 与 128 的分水岭
> `Integer a = 127, b = 127; a == b` 为 **true**（同一缓存对象）；换成 `128` 则为 **false**（各自 new）。包装类比值**一律用 `equals`**。

> [!warning] 自动拆箱会 NPE
> `Integer` 为 null 时参与运算或赋给 int 会触发拆箱抛 `NullPointerException`；三目 `flag ? integerObj : 0` 也因类型对齐把对象拆箱。

- 存储分两处：基本类型局部变量占栈帧的局部变量表，包装类对象是堆里的对象（字段另存 value），见 [[JVM 运行时数据区]]。
- 取舍：金额用 `BigDecimal(String)` 构造，状态 / 金额 / 计数类字段优先包装类以表达 null；循环里的装箱是隐形开销，集合只能装对象，装箱见 [[Java Collection]]。

<details>
<summary>面试问答 (4题)</summary>

Q：127 装箱后 `==` 为 true，128 却为 false？

A：`Integer.valueOf` 缓存了 -128~127，区间内复用同一对象；128 各自 new，`==` 比引用故 false（比值一律 `equals`）。

Q：`0.1 + 0.2` 为什么不等于 0.3？

A：二进制浮点无法精确表示 0.1，误差累加得 `0.30000000000000004`；金融场景用 `BigDecimal`，且必须字符串构造。

Q：`b = b + 1;` 报错而 `b += 1;` 能过？

A：byte/short/char 参与算术先提升为 int，赋回 byte 属大转小需强转；`+=` 自带隐式强转，等价 `b = (byte)(b + 1)`。

Q：`short s = 1; s = s + 1;` 与 `long` 转 `float` 的共同点？

A：都考自动转换方向：`s + 1` 提升成 int 不能自动赋回 short；`long → float` 反而自动，因为看**取值范围**而非精度，但 float 有效位只有 24 位会丢精度。

</details>

<summary>常见误区 (3条)</summary>

- 误区：boolean 占 1 字节。规范没规定位数、只规定了取值，HotSpot 里单独字段常按 int、`boolean[]` 常按 byte。
- 误区：包装类 `==` 比的是值。`==` 永远比引用，只是缓存区间内恰好命中同一对象。
- 误区：`new BigDecimal(0.1)` 能精确表示 0.1。误差被完整保留——它得到 `0.1000000000000000055511151231257827`，必须用字符串构造或 `BigDecimal.valueOf(0.1)`。

</details>
