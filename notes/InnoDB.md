# InnoDB

:::lede
InnoDB 是 MySQL 的事务型存储引擎，支持 ACID 事务、行级锁与 MVCC，负责数据的组织、并发控制与崩溃恢复。
它是 MySQL 的默认引擎。
**边界：** 引擎只管存取 · 解析、优化、连接归 Server 层
:::

改一行不碰磁盘上的行，而在内存里改它所在的 16KB 页，改动以顺序日志落盘（WAL，见 [[MySQL 日志]]）。

## 引擎定位：InnoDB 与 MyISAM

MySQL 5.5 起 InnoDB 是默认引擎，8.0 起系统表也全换成 InnoDB；问 MyISAM 是问能力边界：

| 维度 | InnoDB | MyISAM |
|---|---|---|
| 事务 | ✅ ACID，undo / redo 落地（见 [[MySQL 日志]]） | ❌ 无事务 |
| 锁粒度 | 行锁（默认），并发写不同行不冲突 | 表锁，一次写锁整张表 |
| 外键 | ✅ | ❌ |
| 崩溃恢复 | ✅ redo 重放 + undo 回滚 | ❌ 表可能损坏，需 repair |
| 索引叶子存什么 | 聚簇索引存整行，二级索引存主键值 | 非聚簇，叶子存行的物理地址 |
| COUNT(*) | 必须扫描 | 表头维护行计数，无 WHERE 时直接返回 |
| 全文索引 | ✅（5.6 起） | ✅ |

InnoDB 不存行数：各事务可见行集不同，固定数字必然对部分事务是错的，只能遍历最小的可用二级索引（无则扫聚簇索引）；`COUNT(*)` 与 `COUNT(1)` 无性能差别。

## 内存结构：四个部件

| 部件 | 作用 |
|---|---|
| Buffer Pool | 缓存数据页与索引页，读写先在这里发生 |
| Change Buffer | 目标索引页不在池里时先记改动，读入再合并 |
| Adaptive Hash Index | 为频繁等值访问的页建内存哈希，省掉 B+ 树下探 |
| Log Buffer | redo 落盘前的中转站（刷盘策略见 [[MySQL 日志]]） |

## Buffer Pool：读写在内存里发生

读写单位是页（默认 16KB）：读一行先把页读进池，改一行也在池里改，改完即脏页、等后台刷回磁盘。

| 配置 | 默认 | 怎么定 |
|---|---|---|
| innodb_buffer_pool_size | 128MB | 专用库机器可到物理内存 80%（官方原话「up to 80%」）；同 [[分库分表]]「热数据装得下就够用」 |
| innodb_buffer_pool_instances | 8（池小于 1GB 时为 1） | 大池拆多实例，减少池元数据争用 |

池里的页按（表空间号，页号）定位，三条链表各管一段生命周期：

| 链表 | 装什么 | 作用 |
|---|---|---|
| free | 空闲页 | 读入新页时从这里分配 |
| LRU | 已读入、可被淘汰的页 | 池满时从冷端淘汰 |
| flush | 脏页，按变脏先后排队 | 刷盘队列，checkpoint 推进靠它（见 [[MySQL 日志]]） |

### 改进 LRU：新页为什么插在中点

标准 LRU 新页插链表头，全表扫描会把只读一次的页灌满池、冲掉热页；InnoDB 改为中点插入：

```chain
读入新页 | 插在 young 与 old 的分界点 | 中点
短暂访问 | 时间窗内不晋升 | 防污染
反复访问 | 超时才升到 young 头部 | 真热页
淘汰 | old 尾部先出局 | 兜底
```

- young（热端，约 5/8）与 old（冷端，约 3/8）由 `innodb_old_blocks_pct` 控制，默认 **37**。
- old 段的页要**距首次访问超过 `innodb_old_blocks_time`（默认 1000 毫秒）**再被访问才晋升到 young 头部；扫描页的连续访问全落在时间窗内，晋升不了。
- 大表扫描多时官方举例把 `innodb_old_blocks_pct` 调到 5。

### 预读与刷脏

- 线性预读：一个区（64 页）中顺序读到的页达到 `innodb_read_ahead_threshold`（默认 56，0~64）就异步预读**下一个区**；随机预读默认关闭。
- 刷脏：8.0 由 page cleaner 线程做；脏页占比过 `innodb_max_dirty_pages_pct_lwm`（默认 10%）提前刷、到 `innodb_max_dirty_pages_pct`（默认 90%）转激进刷；自适应刷脏跟 redo 生成速度调整，避免 redo 写满被迫强刷（sharp checkpoint）（见 [[MySQL 日志]]）。
- `innodb_flush_neighbors`：8.0 默认 0（SSD 推荐）；5.7 默认 1。

## Change Buffer：推迟二级索引的随机读

改一行要连带改每个二级索引，这些页多半不在池里，读进来又添几次随机读；Change Buffer 先把改动记内存，等页被读进池时再合并（merge）：

| 项 | 内容 |
|---|---|
| 适用对象 | **非唯一二级索引**的 INSERT / UPDATE / DELETE 改动 |
| 生效前提 | 目标索引页不在 Buffer Pool 中 |
| 存在形式 | 内存里占 Buffer Pool 的一部分，落盘在系统表空间；改动同样记 redo，宕机不丢 |
| 合并时机 | 页被读入时、主线程空闲时、慢关闭时 |
| 上限 | `innodb_change_buffer_max_size` 默认 25（占池子百分比，最大 50） |

> [!note] 唯一索引为什么用不上
> 唯一索引写入必须**立刻**读页判重，页已被读进来，缓冲无从谈起——这正是「写多读少的表用普通索引更划算」的机理，选型见 [[MySQL 索引]]。含降序索引列的二级索引同样不支持。

合并的账迟早要还：受影响的二级索引多、改动量大时 merge 可能持续**数小时**，提交后继续、甚至跨重启——缓冲只是推迟随机读。

## 自适应哈希索引：给热页抄近路

B+ 树查一行要 3~4 次页访问；某个索引页等值查找特别频繁时，InnoDB 自动用索引键前缀为它建内存哈希，下次一次定位。

- 「自适应」= 建删由 InnoDB 自判，只能整体开关：`innodb_adaptive_hash_index` 默认 ON，按 `innodb_adaptive_hash_index_parts`（默认 8，最大 512）分片减少争用。
- 只服务等值与直接定位；范围扫描、`LIKE '%x%'` 这类用不上。
- 重负载下可能反成争用源：`SHOW ENGINE INNODB STATUS` 的 SEMAPHORES 段见 rw-latch 等待，就调大分片数或关掉。

## 磁盘结构：从表空间到页

| 层 | 单位 / 内容 | 为什么这么分 |
|---|---|---|
| 页 page | **16KB**，InnoDB 最小 IO 单位 | 一页即一次 IO 成本，树高即页访问次数（见 [[MySQL 索引]]） |
| 区 extent | 64 个连续页 = **1MB** | 按区分配，范围扫描与预读才连续 |
| 段 segment | **每个索引两个段**：叶子段 + 非叶段 | 叶子页物理连续，范围扫描顺序读 |
| 表空间 tablespace | 逻辑容器：系统、独立（每表一个 .ibd）、undo、临时表空间 | 独立表空间才能单表回收空间，`innodb_file_per_table` 默认开 |

`innodb_page_size` 只接受 4 / 8 / 16 / 32 / 64KB 五档，初始化时定死、全实例统一；16KB 是默认折中。行格式默认 `DYNAMIC`：超长 VARCHAR / BLOB 溢出到溢出页，行内只留 20 字节指针。

## 双写缓冲：WAL 兜不住的那一种崩

redo 能救「已提交但页还在内存」的改动，救不了**页写了一半**：16KB 页刷盘途中断电会留下撕开的半页，而 redo 是页级物理日志、重放前提是页本身完好。双写把写一页拆成两步：

```chain
刷脏页 | 从 buffer pool 取出待刷的页 | 起点
写双写区 | 连续大块写 + 一次 fsync | 保险
写真实位置 | 各表空间里的随机位置 | 落地
恢复校验 | 页损坏就用双写区副本覆盖 | 兜底
```

> [!note] 写两遍不等于两倍开销
> 第一遍是大块顺序写、只发一次 `fsync()`；只有第二遍是原来那些随机写。

8.0.20 起双写区有独立文件（`#ib_16384_0.dblwr` 这一族），此前寄生在系统表空间；`innodb_doublewrite` 默认开启，8.0.30 起支持 `DETECT_ONLY`（只检测不恢复）。

## 落地：ACID 对应到哪个部件

| 承诺 | 谁负责 | 展开 |
|---|---|---|
| 原子性 | undo log 反向回滚 | [[MySQL 日志]] |
| 持久性 | redo log（WAL）+ 双写缓冲 | [[MySQL 日志]]、本篇 |
| 隔离性 | 行锁 / Next-Key Lock + MVCC 版本链 | [[MySQL 事务隔离级别]]、[[MVCC]] |
| 一致性 | 上述三者合力，外加约束与外键 | — |

<details>
<summary>面试问答 (2题)</summary>

Q：Change Buffer 是什么，为什么唯一索引用不了？

A：非唯一二级索引的写改动，目标页不在池里时先记内存、读入再合并；唯一索引必须立刻读页判重。

Q：有 redo log 为什么还需要双写缓冲？

A：redo 重放前提是页完好，页写一半留下的撕裂半页它补不了；双写先顺序写双写区（一次 fsync）再写真实位置。

</details>

<summary>常见误区 (2条)</summary>

- 误区：Buffer Pool 缓存行。单位是页（16KB），改一行整页变脏。
- 误区：InnoDB 的 COUNT(*) 和 MyISAM 一样快（或一样慢）。MyISAM 读表头计数直接返回；InnoDB 因可见行集不同必须扫描，走最小的二级索引。
