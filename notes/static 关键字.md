# static 关键字

## 思维链路速查

```chain
类级 vs 实例级 | 一条分界线 | 核心
修饰形态 | 变量/方法/块/内部类/导入 | 速查
内存与初始化 | 类加载时定型 | 机制
final 与单例 | 实战落点 | 推论
面试问答 | 高频考点 | 复盘
```

static 的本质只有一句——它属于「类」而不是「对象」：全类共享同一份，且不必 new 就能用。立住「类级 vs 实例级」这条分界线，修饰变量 / 方法 / 代码块 / 内部类只是同一条思想的四种落地，内存归属、初始化时机、线程安全都是这条线的推论。

## 类级成员 vs 实例成员

| 维度 | 实例成员（无 static） | 类成员（static） |
|---|---|---|
| 归属 | 每个对象各一份 | 全类共享一份 |
| 访问方式 | `obj.field` | `Class.field`（也允许 `obj.field`，编译期转类） |
| 内存 | 随对象在堆 | 随 Class 对象（堆），类元信息在元空间 |
| 生命周期 | 对象 GC 才释放 | 类卸载才释放（几乎伴随整个 JVM） |
| 可否访问对方 | 实例方法可访问静态 | 静态方法**不能**直接访问实例成员 |

> [!warning] 静态方法没有 this / super
> 静态方法属于类、不绑定任何对象，因此方法体内不能用 `this`、`super`，也不能直接读实例字段 / 调实例方法——必须先拿到一个对象实例。这是所有「静态方法限制」的总根源。

## 修饰形态速查

| 修饰目标 | 写法 | 要点 |
|---|---|---|
| 静态变量 | `static int n` | 共享计数器、常量容器；类加载时定型 |
| 静态方法 | `static void f()` | 工具类（Math、Collections）、工厂方法 |
| 静态代码块 | `static { ... }` | 类初始化时执行一次，做静态资源准备 |
| 静态内部类 | `static class Inner` | 不持有外部类引用，可独立 new |
| 静态导入 | `import static ...` | 省略类名调静态成员，慎用 |

> [!note] static 不能修饰局部变量
> Java 只认「成员级」static；方法里的局部变量写 `static` 直接编译报错。这是和 C/C++ 的关键区别，常被拿来挖坑。

> [!tip] 工具类的本质
> `java.lang.Math`、`java.util.Collections`、`java.util.Arrays` 全是静态方法集合——无状态、无实例，调用即算。这类类通常把构造器私有化以防被 new。

## 内存归属与初始化时机

静态成员随「类」加载定型：JVM 规范把它们归在方法区，HotSpot 里 JDK 8 起方法区实现为元空间 Metaspace（类元信息放本地内存），而静态变量本身与 Class 对象一起落在堆中；类卸载才回收，实际几乎伴随整个 JVM 生命周期。

初始化分两步（类加载过程见 [[类加载过程]]、整体流程见 [[类加载]]）：
- **准备阶段**：静态变量分配内存并赋零值（默认值）。
- **初始化阶段（<clinit>）**：按源码顺序执行静态变量赋值 + 静态代码块，且**只执行一次**；父类 <clinit> 先于子类。

```branch
01: 类何时触发初始化
02: 按动作分流
- new / 访问静态成员 | 主动使用 | 触发 <clinit>
- 子类初始化 | 父类先 init | 父静态先跑
- 反射 Class.forName | 主动使用 | 触发
- 仅定义引用 / 数组声明 | 被动使用 | 不触发
```

> [!danger] 静态块只跑一次的前提
> 同一个类加载器下，<clinit> 由 JVM 加锁保证只执行一次。多层类加载器（如热部署）可能让同一份类被加载多次、静态块跑多次——这与 [[双亲委派模型]] 是否被打破直接相关。

## 静态内部类 vs 非静态内部类

| 维度 | 非静态内部类 | 静态内部类 |
|---|---|---|
| 持有外部类引用 | 隐式持有（含 this） | 不持有 |
| 创建方式 | `outer.new Inner()` | `new Outer.Inner()` |
| 访问外部成员 | 能访问实例与静态 | 只能访问外部静态成员 |
| 内存泄漏风险 | 有（内部类长生命周期拖住外部） | 无 |

> [!tip] 单例的推荐写法就靠它
> 「静态内部类持有实例」实现懒加载单例：外部类加载时内部类不加载，首次调 `getInstance()` 才加载并初始化实例，线程安全由 <clinit> 一次性保证。完整写法与 double-checked locking 对比见 [[DCL]]。

## 静态方法不能被重写（override）

静态方法参与的是「隐藏（hide）」而非「重写」：调用方在**编译期**就按引用声明的类型绑定方法，不享多态。

```java
class A { static void f() { System.out.println("A"); } }
class B extends A { static void f() { System.out.println("B"); } }

A x = new B();
x.f();          // 打印 "A"：看的是编译期类型 A，不是运行时 B
```

> [!warning] 重写看运行时，隐藏看编译期
> 实例方法重写是动态绑定（运行时按对象实际类型）；静态方法调用是静态绑定（编译期按声明类型）。所以「父类静态方法被「重写」后表现多态」是错的——它压根没多态。

## 落地：易错点代码

> [!note] 五组对照
> 静态不能访问实例、static 块只跑一次、隐藏非重写、static final 编译期内联、静态内部类不持有外部引用。

```java
class Demo {
    static int s = 0;          // 类级共享
    int i = 0;                 // 实例级各自一份

    static { System.out.println("clinit 一次"); } // 类加载时跑一次

    static int inc() { return s++; }   // 共享计数，线程不安全
    // static void g() { return i; }   // 编译错：静态方法不能碰实例成员

    void h() { s++; i++; }             // 实例方法可访问静态
}

// 编译期常量：基本类型 / String 字面量在编译期直接内联
class C {
    static final int N = 10;                  // 用到处被替换成 10
    static final String S = "hi";             // 同上，常量池
    static final List<Integer> L = new ArrayList<>(); // 引用类型：非编译期常量，运行时才初始化
}

// 静态导入
import static java.lang.Math.max;
int m = max(1, 2);        // 省去 Math.
```

> [!danger] static 变量不是线程安全的
> 共享计数器 `s++` 是读-改-写复合操作，多线程下会丢更新；要并发安全得加锁或改用 [[CAS 与原子类]] 的 `AtomicInteger`。static 只解决「共享」，不解决「并发」。

<details>
<summary>面试问答 (5题)</summary>

Q：static 变量存在哪里？

A：JVM 规范归方法区；HotSpot JDK 8 起方法区实现为元空间 Metaspace（类元信息在本地内存），而静态变量本身与 Class 对象一起在堆中。生命周期随类卸载才结束，实际几乎伴随整个 JVM。

Q：静态变量和实例变量有什么区别？

A：静态变量类级共享一份、随类加载定型、可直接用类名访问；实例变量每个对象各一份、随对象在堆、必须 new 出来才能用。静态方法不能访问实例变量，反之可以。

Q：静态方法为什么不能被重写？

A：静态方法属于类、调用是编译期静态绑定（按声明类型），不享多态；子类同名静态方法只是「隐藏」父类方法，运行时按引用声明类型决定调谁，不是动态绑定的重写。

Q：static 代码块什么时候执行，执行几次？

A：类**首次主动使用**时（new、访问静态成员、反射等）触发 <clinit>，按源码顺序执行静态变量赋值 + 静态块；同一类加载器下受 JVM 加锁保证只执行一次。仅声明引用、定义数组等被动使用不触发。

Q：static 和 final 一起用有什么用？

A：static final 定义常量。基本类型与 String 字面量在编译期内联（用到处直接替换成值，运行时不依赖类加载）；引用类型仍运行时初始化。它不可变所以只读共享是线程安全的，但可变静态字段仍要自己处理并发。

</details>

<details>
<summary>常见误区 (6条)</summary>

- 误区：static 变量在方法区 / 永久代。JDK 8 起永久代已移除，类元信息改放元空间，静态变量与 Class 对象在堆中——说「永久代」是旧版本的过时说法。
- 误区：静态方法能被重写实现多态。静态方法只会被「隐藏」，调用按编译期类型，不享运行时多态。
- 误区：static 保证线程安全。static 只解决「共享」，不解决「并发」；`s++` 这类复合操作仍需同步或原子类。
- 误区：static 方法里能用 this。static 不绑定对象，没有 this / super，也读不到实例成员。
- 误区：子类初始化不会触发父类静态块。父类 <clinit> 一定先于子类执行，这是初始化顺序的铁律。
- 误区：static 可以修饰方法里的局部变量。Java 不支持局部 static，编译直接报错。

</details>
